# MVP — Produit minimum viable

Le MVP (Minimum Viable Product, produit minimum viable) est la première version du produit mise en production avec le minimum de fonctionnalités nécessaires pour répondre aux besoins des premiers utilisateurs et valider les hypothèses fondamentales.

!!! note

    Le MVP s'inscrit dans le [cycle de vie produit](cycle-de-vie-produit.md) à l'étape 3. Il est construit à partir des apprentissages du [parcours utilisateur](../concevoir/parcours-utilisateur.md) et du [story mapping](../concevoir/story-mapping.md).

### Pourquoi construire un MVP ?

Le MVP remplit deux finalités complémentaires :

* **Dérisquer** : valider tôt que le produit répond à un besoin réel, sans investir dans des fonctionnalités non vérifiées
* **Générer de la connaissance** : apprendre des premiers usages réels, sur les comportements des usagers et sur la solidité technique du produit

Un MVP n'est pas un prototype ni une démonstration : c'est un produit opérationnel, en production, entre les mains de vrais utilisateurs.

### Prioriser le contenu du MVP : MoSCoW

La méthode MoSCoW permet de distinguer ce qui est indispensable de ce qui peut attendre :

| Niveau | Signification | Question clé |
|---|---|---|
| **Must** (Doit) | Indispensable : sans ça, le MVP ne peut pas fonctionner | "Le produit peut-il être utilisé sans cette fonctionnalité ?" |
| **Should** (Devrait) | Important mais non bloquant ; reportable à la prochaine itération | "Quel est l'impact sur la valeur si on l'enlève ?" |
| **Could** (Pourrait) | Souhaitable si le temps le permet ; aucun effet sur la valeur de base | "Serait-ce vraiment manqué ?" |
| **Won't** (Ne sera pas) | Explicitement hors périmètre de ce MVP, noté pour éviter la dérive | "Pourquoi l'écarter maintenant ?" |

!!! note

    Pour affiner la priorisation entre plusieurs sujets en concurrence, consulter la [matrice RICE](matrice-rice.md).
